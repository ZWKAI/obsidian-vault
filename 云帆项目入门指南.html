从线索建立客户档案

销售跟进线索，满足转换条件后可以保存客户草稿或提审。客户档案承载后续商机、合同及业务租户的客户归属。

把一次销售机会推进到签约

客户可以有多个商机。商机推进到 S5 且尚未签约时，销售选择合同类型，从管理后台进入 OMS 合同新建页。

用合同明确销售和签约双方

合同关联客户、销售组织、签约主体及商品明细。以国内销售合同为例，合同经过审批、完成签约后生效，OMS 再根据合同细类判断是否生成订单。

用一张订单跟踪交付和资金

软件商品可向业务租户下发授权，硬件商品可生成发货单。符合条件的订单可以发起收款、开票。下游单据将数量或金额回写订单，支撑后续核对。

分润如何取得 OMS 的租户资料

OMS 的 Maven 配置直接引用了分润模块。反过来，分润在展示账单时也需要业务租户名称。分润服务调用公共接口 ProfitCorporationQueryApi，由 OMS 在同一进程中提供实现并读取租户数据。接口放在 yunfun-common，因此两个模块能交换数据，同时保持 Maven 依赖单向。账单服务 · 公共查询接口 · OMS 实现

阅读模块边界

yunfun-framework 提供 Web、安全、MyBatis、Redis、多租户等 Starter，yunfun-dependencies 管理依赖版本。跨业务模块约定通过对方的 api 包或 framework.common.biz 契约协作。yunfun-harness 用 ArchUnit 检查新出现的越界引用，并通过基线记录历史例外。分层规则 · 历史例外清单

仓库还保留 yunfun-module-ai 的源码。当前根 POM 与启动模块 POM 都注释了它，默认启动装配的是表中八个模块。根 POM · 启动模块 POM · Spring Boot 启动类

三条跨模块业务链路

商机签约与合同转单

销售在 CRM 跟进客户商机。进入 S5 且尚未签约时，可在商机列表选择合同类型，转到 OMS 的合同新建页填写并提交。CRM 随后可按客户、S5 进入时间和保护期查询已签销售合同。排查“发起签约”按钮应先看前端路由，CRM 的 startContractSign 后端方法仍返回“合同模块未集成”。

合同进入“已生效”时，OMS 状态机检查合同细类。可自动转单的八类为国内销售、海外销售、中餐出海销售、续费销售、服务商销售、试用、测试和服务商订购。转单服务读取合同商品明细、创建订单，并把订单 ID 回写合同。

以试用订单为例，转单服务发布订单生效事件。事务提交后，自动授权监听器接收事件，调用权益服务下发授权。测试订单走同一监听器，续费订单交给专门的续费监听器。

从售前申请到实施项目

销售围绕客户发起售前申请。售前模块调用 BPM 创建流程，将流程实例 ID 记在申请上。审批结果监听器根据业务键找到申请，再核对流程实例 ID，避免旧流程覆盖新一轮提交。审批通过、驳回和撤回分别回写为已通过、已驳回和草稿。

审批通过后，有权限的人员可通过 POST /admin-api/presale/work-order 建立工单。同一申请最多保留一张有效工单，取消后可重建。工单继承客户和销售归属，之后可分派、登记工时。

需要交付时，在 CRM 实施项目上关联已有售前工单。桥表 pdm_project_presale_work_order 存放项目与工单的 ID，可以从两侧查询。创建工单和绑定项目是两个独立操作。

从通道源账单到租户分润

Profit 按批次导入支付通道的源账单。执行结算时，跑批服务校验交易月份、规则快照和导入结果，交给计算器生成业务租户的分润汇总与明细。账单分别保留交易月、结算月、支付通道和币种，可据此解释同一客户名下的多笔记录。

发布服务校验汇总和明细金额，写入 profit_tenant_bill 与 profit_tenant_bill_detail，再将该通道、该结算月的新版本标为当前版本。OMS 负责业务租户及销售归属，归属变更时调用 Profit 的 API 同步账单和商家返佣规则。

组织与租户

同一份合同上，客户、归属销售组织和签约主体回答依次对应采购方、负责销售的组织和实际签署合同的主体。交付权益和计算分润时，还要找到该客户对应的业务租户。

概念与源码管理职责与其他对象的关联
部门System 用 system_dept 维护组织树、上下级和负责人。组织树包含分公司、部门和销售组织，用户关联所属部门。销售组织的 organizationId 指向部门 ID。
销售组织CRM 用 crm_sales_org 描述销售组织的性质、区域和业务模式。客户或合同可以记录销售归属。销售组织与可用签约主体通过 crm_sales_org_signing_entity 关联。
签约主体CRM 用 org_signing_entity 记录我司或服务商主体名称、注册信息和企业识别码。OMS 的合同及签约方记录保存对应主体 ID 和名称，供签署环节使用。
系统租户System 用 system_tenant 管理平台租户、套餐、状态和到期时间。框架使用 tenantId 表示数据隔离范围。分润账单也记录这个 ID。
业务租户OMS 用 oms_corporation 管理客户名下承接授权、支付配置和分润的经营实体。通过 customerId 关联 CRM 客户。一个客户可有多个业务租户。分润账单用 corporationId 标识结算对象。

第一次读源码的路线

以下链接指向本机的 ai-starter 仓库。先认识服务如何启动，再选一条与你工作有关的单据追下去。

  1. 从装配入口认清系统边界

    先打开 服务装配清单，对照 Spring Boot 启动类，再读 分层规则，看清模块和公共框架各自负责什么。

  2. 跟一次客户列表请求

    从管理端的 客户列表页面 进入，按系统架构中的顺序看请求封装、权限检查、Service 和 Mapper。需要表字段时可查 数据模型索引。

  3. 找出一份合同的上游和下游

    从 商机签约入口 走到 合同状态机，最后跟到 订单生成服务，找出创建和回写关联单据的两个位置。

  4. 核对移动端的两类入口

    验收 H5 调用实施工单接口。APP 首页 汇总 BPM 待批和 system 未读通知，当前待办线索数固定返回 0。

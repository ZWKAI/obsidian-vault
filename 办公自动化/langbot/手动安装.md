# LangBot 手动部署完整方案（生产环境）

既然你决定手动部署，下面给你一套**适合生产环境的完整手动部署方案**。虽然官方文档提到"Unix-like 系统上请优先考虑使用 Docker 部署"，但手动部署在以下场景确实更有优势：

- 需要进行**二次开发**或代码修改
- 想**深度定制**某些功能
- 对 Docker 不熟悉，希望**完全掌控**环境

---

## 📋 一、环境准备

### 1.1 服务器要求

| 项目 | 最低配置 | 推荐配置 |
|------|----------|----------|
| **CPU** | 2核 | 4核 |
| **内存** | 4GB | 8GB |
| **操作系统** | Ubuntu 20.04+ / CentOS 8+ | Ubuntu 22.04 LTS |
| **Python** | 3.11+ | 3.11 或 3.12 |

### 1.2 安装必要工具

```bash
# 更新系统
sudo apt update && sudo apt upgrade -y   # Ubuntu/Debian
# 或
sudo yum update -y                        # CentOS/RHEL

# 安装 git
sudo apt install git -y                   # Ubuntu/Debian
# 或
sudo dnf install git -y                   # CentOS/RHEL

# 安装 uv（Python 包管理器）
pip install uv
# 或使用官方安装脚本
curl -LsSf https://astral.sh/uv/install.sh | sh
```

## 🚀 二、部署 LangBot

### 2.1 下载源码

```bash
# 克隆仓库（不是 Release 包，Release 包已包含 WebUI）
git clone https://github.com/langbot-app/LangBot
cd LangBot

# 如果中国大陆服务器，使用以下地址加速
git clone https://hub.fastgit.xyz/langbot-app/LangBot
cd LangBot

# 手动下载
wget https://github.com/langbot-app/LangBot/releases/download/v4.9.7/langbot-v4.9.7-all.zip


```

> **注意**：官方文档指出，如果要包含 WebUI，需要下载 Release 页面的 `langbot-xxx-all.zip` 压缩包，而不是直接 clone 源码。上面的 clone 命令会拉取完整代码，后续需要单独构建前端。

### 2.2 安装 Python 依赖

```bash
# 使用 uv 同步依赖（推荐，速度快）
uv sync

# 国内用户可使用清华源加速
pip install uv -i https://pypi.tuna.tsinghua.edu.cn/simple
uv sync
```

`uv sync` 会根据 `pyproject.toml` 自动创建虚拟环境并安装所有依赖。
 临时修改uv镜像：
 export UV_DEFAULT_INDEX="https://pypi.tuna.tsinghua.edu.cn/simple"
### 2.3 构建前端（如果 clone 源码）

```bash
cd web

# 安装 Node.js 依赖
npm install
# 或使用 pnpm（更快）
pnpm install

# 构建生产版本
npm run build
# 或
pnpm run build

cd ..
```

构建完成后，前端静态文件会生成在 `web/out/` 目录。

### 2.4 首次运行生成配置

```bash
# 在项目根目录下运行
uv run main.py
```

首次运行会自动生成配置文件到 `data/config.yaml`。看到以下输出后按 `Ctrl+C` 退出：

```
以下文件不存在，已自动生成，请按需修改配置文件后重启：
- data/config.yaml
```

## ⚙️ 三、生产环境配置

### 3.1 修改核心配置 `data/config.yaml`

```yaml
# API 服务配置
api:
  host: "0.0.0.0"          # 监听所有网卡，允许外部访问
  port: 5300               # WebUI 端口
  secret_key: "请修改为一个复杂的随机字符串"

# 数据库配置（生产环境建议使用 PostgreSQL）
database:
  type: "sqlite"           # 小规模用 sqlite 足够
  path: "data/langbot.db"

# 日志配置
log:
  level: "INFO"            # 生产环境用 INFO，调试用 DEBUG
  file: "data/langbot.log"
```

### 3.2 配置大模型

LangBot 支持多种大模型接入，以下以 **OpenAI 兼容接口**为例：

在 `data/config.yaml` 中添加模型配置：

```yaml
models:
  - name: "gpt-3.5-turbo"
    provider: "openai"
    api_key: "your-api-key"
    base_url: "https://api.openai.com/v1"
    model: "gpt-3.5-turbo"
```

> 国内用户可使用**硅基流动**等第三方 API 服务，参考其提供的接入文档。

## 🔄 四、进程管理（生产环境关键）

手动部署最大的问题是**进程管理**。为了让它能在后台稳定运行并开机自启，需要配置系统服务。

### 4.1 创建 systemd 服务文件

```bash
sudo nano /etc/systemd/system/langbot.service
```

粘贴以下内容（**请替换路径为你的实际路径**）：

```ini
[Unit]
Description=LangBot Service
After=network.target

[Service]
Type=simple
User=app                           # 替换为你的用户名
WorkingDirectory=/home/app/LangBot # 替换为项目实际路径
Environment="PATH=/home/app/.local/bin:/usr/local/bin:/usr/bin"
ExecStart=/home/app/.local/bin/uv run main.py
Restart=on-failure
RestartSec=10
StandardOutput=append:/home/app/LangBot/data/langbot.log
StandardError=append:/home/app/LangBot/data/langbot-error.log

[Install]
WantedBy=multi-user.target
```

### 4.2 启动并设置开机自启

```bash
# 重新加载 systemd 配置
sudo systemctl daemon-reload

# 启动服务
sudo systemctl start langbot

# 设置开机自启
sudo systemctl enable langbot

# 查看服务状态
sudo systemctl status langbot

# 查看实时日志
journalctl -u langbot -f
```

## 🔄 六、更新与维护

### 6.1 手动更新步骤

```bash
cd /home/app/LangBot

# 停止服务
sudo systemctl stop langbot

# 拉取最新代码
git pull

# 更新依赖（如有变化）
uv sync

# 重新构建前端（如有更新）
cd web && npm run build && cd ..

# 启动服务
sudo systemctl start langbot
```

### 6.2 从 Release 包更新

官方文档提到，手动部署还可以直接下载 Release 压缩包：

```bash
# 下载最新版本
wget https://github.com/langbot-app/LangBot/releases/download/v4.9.7/langbot-v4.9.7-all.zip

# 解压覆盖
unzip -o langbot-xxx-all.zip -d /home/app/LangBot

# 重启服务
sudo systemctl restart langbot
```

## ⚠️ 七、常见问题与注意事项

| 问题 | 解决方法 |
|------|----------|
| **端口被占用** | 修改 `data/config.yaml` 中的 `api.port` |
| **前端无法访问** | 确认 WebUI 已正确构建到 `web/out/` |
| **uv 命令找不到** | 重新加载 shell：`source ~/.bashrc` 或重开终端 |
| **Python 版本过低** | 使用 `pyenv` 或 `conda` 安装 Python 3.11+ |
| **systemctl 权限不足** | 使用 `sudo`，或确保用户有服务管理权限 |

## 💡 方案总结

这套手动部署方案的核心是 **systemd + uv**：

- **`uv`**：现代化的 Python 包管理器，比 pip 快得多
- **systemd**：系统级进程管理，保证服务持续运行
- **独立配置文件**：`data/config.yaml` 集中管理所有配置

相比 Docker，手动部署让你对每个环节都有完全的控制权，适合**二次开发**和**深度定制**的场景。如果你想在正式环境长期运行，建议保留 systemd 服务配置，这样即使服务器重启也能自动恢复。

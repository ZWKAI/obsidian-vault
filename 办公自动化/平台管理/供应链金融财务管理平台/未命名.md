
# 还款模块 V0.2（最终业务流程）

## 一、开发目标

实现保理业务每月还款数据自动处理，实现：

> **一键生成还款入账底稿。**

人工只需要：

* 输入月份
* 放入综合核算分析表
* 放入客商编码表

程序自动完成后续所有工作。

---

# 二、数据来源

原始数据全部来源于：

> 综合核算分析表

整个程序只有一个业务数据源。

客商辅助资料来源于：

> 客商编码.xlsx

除此之外，不依赖其它Excel维护数据。

---

# 三、程序整体流程

```
综合核算分析表
        │
        │
输入月份（例如6月）
        │
        ▼
筛选当月还款数据
        │
        ▼
生成还款明细
        │
        ▼
生成还款数透
        │
        ▼
匹配客商编码
        │
        ▼
生成入账底稿
```

整个流程只有一次筛选。

后面的所有数据都来源于第一次筛选后的数据。

---

# 四、筛选逻辑

根据输入月份：

例如：

```
6月
```

筛选：

```
结清日期 = 6月
```

同时限定：

```
放款主体
=
北京融汇智达商业保理有限公司
```

这里的目标就是得到：

**本月所有正常还款数据。**

（再保理业务后续已独立拆分为再保理模块。）

---

# 五、生成还款筛选明细

程序首先生成：

```
还款筛选明细-6月
```

要求：

保留筛选后的全部业务字段。

作用：

后续所有统计均来源于此Sheet。

---

# 六、生成还款数透

根据还款明细进行汇总。

汇总维度最终确定为：

```
业务产品

+

放款日期

+

融资企业名称
```

统计金额包括：

```
已还本金

实还利息

实还罚息（仅统计，不参与正常利息分录）
```

一家公司如果有多笔相同维度数据，需要汇总。

---

# 七、客商编码匹配

依据：

```
融资企业名称
```

到：

```
客商编码.xlsx
```

查找：

```
客商编码
```

要求：

全部动态匹配。

禁止写死。

若找不到：

程序停止并提示。

---

# 八、生成入账底稿

最终生成：

```
XX月收（本息）（不含再保理）
```

用于直接导入YS。

---

## 入账内容

主要包括：

### （1）收到本金

银行存款

借

对应：

贷款本金

贷

---

### （2）收到利息

银行存款

借

对应：

利息收入

贷

---

### （3）罚息

罚息金额单独统计。

正常利息分录不包含罚息。

---

# 九、摘要

摘要动态生成。

例如：

```
收到XX公司6月还款本金

收到XX公司6月还款利息
```

月份不能写死。

企业名称不能写死。

---

# 十、项目编码

固定：

```
9999
```

---

# 十一、辅助核算

客户辅助核算：

来源：

```
客商编码.xlsx
```

全部自动带入。

---

# 十二、输出结果

程序最终输出：

```
① 还款筛选明细

② 还款数透

③ XX月收（本息）（不含再保理）
```

程序运行结束即可直接进行财务复核及导入。

---

# 十三、模块设计原则（我们开发过程中反复确认的原则）

1. **单一数据源**：所有业务数据仅来自《综合核算分析表》，避免重复维护。
2. **一次筛选，多处复用**：程序只筛选一次，后续所有统计和底稿都基于这份筛选结果，避免重复计算。
3. **动态生成**：月份、客户、产品、金额、行数、Sheet 名称、摘要等均不得写死。
4. **客商编码自动匹配**：以融资企业名称为键，从《客商编码.xlsx》获取，缺失时程序应提示而不是默认填值。
5. **再保理业务独立处理**：普通还款模块只处理非再保理业务，再保理另由《再保理模块》负责。
6. **直接服务于入账**：最终输出应符合 YS 导入要求，尽量减少人工整理和调整。

# 放款模块 V1.0 已确认框架

## 1. 原始数据来源

所有业务数据来源于：

```text
综合核算分析表
```

程序不应人工录入放款业务明细，也不应把当月明细直接写死在代码中。

---

## 2. 月份采用交互模式

运行程序时输入处理月份，例如：

```text
请输入月份：6
```

月份应动态控制：

* 放款日期筛选；
* Sheet名称；
* 凭证摘要；
* 输出文件名称。

不能固定为6月。

---

## 3. 放款主体

处理主体为：

```text
北京融汇智达商业保理有限公司
```

但我当前无法确认冻结版的最终筛选条件是否仅包含放款主体和放款月份，还是还包含资金归属、产品类型、订单状态等条件。

---

## 4. 客商编码

客商编码不能写死。

处理逻辑为：

```text
融资企业名称
→ 到客商编码文件查找
→ 返回客商编码
→ 写入客户辅助核算
```

匹配依据是企业名称。

---

## 5. 动态生成放款明细

放款企业数量、业务产品及金额必须取自综合核算分析表的实际筛选结果。

不能固定：

* 客户数量；
* 客户名称；
* 客商编码；
* 业务产品；
* 放款金额；
* 数据起止行。

---

## 6. 生成入账底稿

冻结版应当包含：

```text
放款筛选明细
放款汇总或放款数透
放款入账底稿
```

但我目前无法准确确认冻结版的：

* Sheet准确名称；
* 汇总维度；
* 底稿列顺序；
* 放款对应银行；
* 凭证科目编码；
* 摘要公式；
* 借贷方顺序；
* 项目编码及其他辅助核算。

这些内容如果没有原脚本或最终Excel，我不能凭记忆补写为“最终确认逻辑”。

```text

→ 按交互月份筛选放款
→ 生成放款明细及汇总
→ 按融资企业匹配客商编码

```

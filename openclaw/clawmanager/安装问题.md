### DNS网络问题：
**永久方案：**
1. 查看当前使用的网络连接名称
	nmcli connection show
	通常输出类似 `ens33` 或 `System eth0`，记下名称（假设为 `eth0`）。
2. # 设置 DNS 服务器（以 114.114.114.114 和 8.8.8.8 为例）
	sudo nmcli connection modify eno1 ipv4.dns "114.114.114.114 8.8.8.8"
3. 让修改生效（重新激活连接）
	sudo nmcli connection up eno1
4.  验证
	cat /etc/resolv.conf
	ping -c 4 www.baidu.com

**临时方案**： 添加 DNS 服务器
	echo "nameserver 8.8.8.8" > /etc/resolv.conf
	echo "nameserver 114.114.114.114" >> /etc/resolv.conf

**验证**
	查看当前 DNS 配置
	cat /etc/resolv.conf
	 测试域名解析
	ping -c 2 www.baidu.com

### 重启clawmanager后上传的skills丢失
 **根本原因**
k3s 部署里，Skill 文件存在 `clawmanager-app` Pod 的 `emptyDir` 中：
/data/object-storage → emptyDir（临时存储）

`clawmanager-app` 重启后（你这边大约 29 分钟前重启过），之前上传的 Skill zip 会全部丢失。MySQL 里还有 Skill 元数据，但实体文件没了，安装就会 500 失败。

---

**解决步骤**
给对象存储加持久化（必做，否则还会丢）
把 `emptyDir` 改成 PVC
`/data/config/clawmanager-object-storage-pvc.yaml`

`local-path` 不能 resize，只能删掉旧 PVC 再建新的：
```
1. 先让 app 释放卷（会短暂不可用）
kubectl scale deployment clawmanager-app -n clawmanager-system --replicas=0

# 2. 删除旧 PVC（里面的 Skill zip 会清空，需之后重新上传）
kubectl delete pvc clawmanager-object-storage -n clawmanager-system

# 3. 用你改好的 100Gi 清单创建
kubectl apply -f /data/config/clawmanager-object-storage-pvc.yaml

# 4. 恢复 app（会自动挂上新 PVC）
kubectl scale deployment clawmanager-app -n clawmanager-system --replicas=1. 先让 app 释放卷（会短暂不可用）
```

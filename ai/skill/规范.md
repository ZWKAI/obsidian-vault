## 标准格式：
#Skill Skills Overview：[https://agentskills.io/home](https://agentskills.io/home)
**结构**
my-skill/
├── SKILL.md          # Required: metadata + instructions
├── scripts/          # Optional: executable code
├── references/       # Optional: documentation
├── assets/           # Optional: templates, resources
└── ...               # Any additional files or directories

- `SKILL.md` 保持在 500 行和 5,000 个 token 以内——仅包含代理每次运行所需的核心指令。当技能确实需要更多内容时，将详细参考资料移至 `references/` 或类似目录中的单独文件。
- 关键在于告诉代理何时加载每个文件。“如果 API 返回非 200 状态码，则读取 `references/api-errors.md`
- 相同的逻辑——构建图表、解析特定格式、验证输出——这表明应该编写一个经过测试的脚本，并将其打包在 `scripts/` 中。

校验工具：
skills-ref: uv run skills-ref validate 地址


## skills加载执行过程：
1. **Discovery** — When the chat session started, the agent scanned default skill directories and found your skill. It read only the `name` and `description`, just enough to know when the skill might be relevant.  
    发现 — 当聊天会话开始时，代理扫描了默认技能目录并找到了你的技能。它只读取了 `name` 和 `description` ，仅足够知道该技能何时可能相关。
2. **Activation** — When you asked about rolling dice, the agent matched your question to the skill’s description and loaded the full `SKILL.md` body into context.  
    激活 — 当你询问掷骰子时，代理将你的问题与技能的描述进行匹配，并将完整的 `SKILL.md` 正文加载到上下文中。
3. **Execution** — The agent followed the instructions in the body, adapting the terminal command to the number of sides in your request.  
    执行 — 代理遵循了正文中的指示，根据您请求的边数调整了终端命令。

## skills编写经验：
1. 有序的步骤
2. 引导并纠正智能体（例如，“使用 X 库而不是 Y”，“检查边缘情况 Z”）
3. 输入/输出格式 — 数据输入和输出的样子
4. 你提供的上下文 — 项目特定的信息、约定或限制，智能体尚未知晓
